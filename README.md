# MaChill

Persistent group chats with a Discord/Messenger-style "watch session" you
can start anytime — YouTube, a local movie file, a Drive movie, or a live
screen share, together, with a video call and side chat. Free hosting on
GitHub Pages, backed by **Supabase** (Postgres + Auth + Realtime) and Google
Drive (storage).

No build step. Plain HTML/CSS/JS — edit and refresh.

## How it's organized

- **Dashboard** (`dashboard.html`) — search people by name or their short
  **MaChill ID**, create a group (pick people while creating it), and jump
  back into any group you're already in.
- **Group** (`group.html`) — a persistent space per group: a **saved chat**
  (always there) plus a **watch session** you start on demand from the
  bottom call bar, Discord-style. Tap **+** in the call bar to pick what to
  share — Web Together (screen share), Google Drive, a local video, or
  YouTube. Whoever starts a share is tagged as the presenter; playback
  control (play/pause/seek) stays shared across everyone. People can
  hide/show the video tiles and chat panel independently — per-person,
  local-only preferences.
- **Invite** — a link + QR code (`dashboard.html?join=<groupId>`) that
  drops whoever opens/scans it straight into the group.

## 1. Set up Supabase (free tier is enough)

1. [supabase.com/dashboard](https://supabase.com/dashboard) → **New project**.
2. Once it's provisioned: **SQL Editor → New query** → paste the entire
   contents of `supabase-schema.sql` from this repo → **Run**. This creates
   every table, the security policies, the auto-profile trigger, and turns
   on Realtime for the tables that need it.
3. **Project Settings → API** → copy the **Project URL** and the **anon
   public** key into `js/supabase-config.js` (`SUPABASE_URL` /
   `SUPABASE_ANON_KEY`).
4. **Authentication → URL Configuration** → set **Site URL** to your
   GitHub Pages URL, and add it under **Redirect URLs** too (e.g.
   `https://yourname.github.io/reponame/dashboard.html`). Add
   `http://localhost:xxxx/dashboard.html` here too if you'll test locally.
   Sign-in will silently fail to return you to the app if this isn't set.

## 2. Set up one Google OAuth client (used for both sign-in and Drive)

1. [Google Cloud Console](https://console.cloud.google.com) → **APIs &
   Services → Credentials → Create credentials → OAuth client ID** → type
   **Web application**.
2. **APIs & Services → Library** → enable the **Google Drive API** (needed
   for Drive mode later).
3. Back in Supabase: **Authentication → Providers → Google** → toggle it
   on, and paste that OAuth client's **Client ID** and **Client Secret**.
   Supabase will show you a **Callback URL** (something like
   `https://xxxx.supabase.co/auth/v1/callback`) — copy it.
4. Back in Google Cloud Console, on that same OAuth client, add:
   - **Authorized redirect URI**: the Supabase callback URL from step 3
   - **Authorized JavaScript origin**: `https://yourname.github.io`
     (and `http://localhost:xxxx` for local testing)

   This one client covers both things: Supabase uses it (server-side) to
   sign people in, and the app separately asks it (client-side, only when
   someone opens Drive mode) for Drive-read permission — that's why it
   needs both a redirect URI *and* a JS origin.
5. Copy the same **Client ID** into `GOOGLE_OAUTH_CLIENT_ID` in
   `js/supabase-config.js`.
6. **OAuth consent screen**: while in "Testing" mode, only accounts you add
   as test users can sign in. Click **Publish App** to open it to anyone —
   Google may show an "unverified app" warning first (people can click
   through **Advanced → Go to MaChill (unsafe)**); full verification is
   only worth doing once you have a real userbase beyond friends.

## 3. Deploy to GitHub Pages (free)

1. Push this folder to a new GitHub repo.
2. Repo → **Settings → Pages** → Source: **Deploy from a branch** → branch
   `main`, folder `/ (root)`.
3. Live at `https://yourname.github.io/reponame/`. No server, no build.

## How the clever bits work

- **Local movie sync**: nobody uploads anything. Each person opens their own
  copy from their device. Once everyone's filename matches, MaChill only
  sends tiny play/pause/seek timestamps through Supabase — the video itself
  never touches the network.
- **Drive movie mode**: whoever has the file pastes a Drive share link
  (sharing set to **Anyone with the link — Viewer**). Everyone else
  downloads their *own* full-quality copy straight from Google's servers,
  then it's synced the same lightweight way. No live streaming mid-movie.
- **Web Together instead of a shared browser**: most major sites block
  being embedded in an iframe — a security feature no code gets around. So
  instead, one person screen-shares their real browser tab (with audio) to
  everyone else, which works on any site.
- **Invite QR**: generated by a free public QR image API from the invite
  URL — no library, nothing uploaded.

## Known limitations, honestly

- **Sign-in is a redirect, not a popup**: Supabase's OAuth flow navigates
  the whole page to Google and back, unlike Firebase's popup. Slightly
  different feel, same result.
- **Call size**: peer-to-peer *mesh* — great for 2–5 people, not built to
  scale past that.
- **No TURN server**: only free public STUN servers are configured. Add one
  to `ICE_SERVERS` in `js/call.js` if people on strict networks can't
  connect — e.g. a [Metered.ca](https://www.metered.ca/tools/openrelay/)
  free tier or self-hosted `coturn`:
  ```js
  { urls: "turn:your-turn-host:3478", username: "...", credential: "..." }
  ```
- **Browser autoplay policies**: some browsers block programmatic video
  playback until the person has interacted with the page at all. One click
  anywhere fixes it for the rest of the session.
- **Drive uploader quota**: Drive's free 15GB counts against whoever
  *uploads*, not whoever downloads.
- **Screen share audio**: strongest in Chrome/Edge; Safari/Firefox support
  is more limited.
- **RLS is permissive-but-authenticated**: any signed-in user can read most
  tables (needed for search/invite previews) but can only write their own
  rows — except group owners, who can also add members when creating a
  group. Fine for a private circle; tighten the policies in
  `supabase-schema.sql` if you need more isolation.
- **Name search** only matches the *start* of a name; ID search is
  exact-match.

## Natural next upgrades

- Swap the Drive paste-a-link flow for the full Google **Picker UI** — see
  [Google's Picker docs](https://developers.google.com/drive/picker/guides/overview).
- Presence dots (online/away) for group members.
- ICE-restart / auto-reconnect if someone's wifi blips mid-call.
- Group avatars/photos instead of initials.

### Data model (Postgres)

```
profiles(id, display_name, avatar_url, machill_id, created_at)
groups(id, name, owner_id, created_at)
group_members(group_id, user_id, display_name, avatar_url, joined_at)
group_messages(id, group_id, user_id, name, photo_url, text, created_at)
call_members(group_id, user_id, display_name, avatar_url, joined_at)
watch_sessions(group_id, active, media_mode, presenter_id,
                started_by, started_at, playback jsonb, updated_at)
signals(group_id, pair_key, kind, channel_key, offer, answer,
        candidates_a, candidates_b, updated_at)
```

`profiles` rows (and their MaChill ID) are created automatically by a
database trigger the moment someone signs in for the first time — see
`handle_new_user()` in `supabase-schema.sql`.
